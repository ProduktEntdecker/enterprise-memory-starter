### 1. Contradiction: rooftop hours

- **Severity:** High. The value sits in FACTS.md row 8 and would reach guests on an event page.
- **Where:** [FACTS.md](../FACTS.md) row 8, [entities/rooftop.md](../entities/rooftop.md), [summaries/C01-programme-extract.md](../summaries/C01-programme-extract.md), [summaries/C02-rooms-and-capacity.md](../summaries/C02-rooms-and-capacity.md)
- **Evidence:**
  - "The rooftop programme from 18:00 is run by a separate organiser" (C01, programme page, 2026-09-13).
  - "Rooftop, n/a seats, only 16:00 to 18:00, special activations" (C02, backoffice export, 2026-09-19).
- **Why it matters:** The two windows do not overlap except at one point in time. A guest reading the programme expects the rooftop to open when the backoffice says it closes.
- **Suggested resolution:** Do not resolve by date. C02 is newer but it is authoritative for seat counts, not for a programme the house does not run. Ask the separate rooftop organiser, then set row 8 to the confirmed window and move the losing value to the history table.
- **Decision by:** unassigned. See finding 3: row 8 has no owner, so there is currently nobody the wiki can point at.

### 2. Stale fact: ticket caps derived from superseded capacities

- **Severity:** High. It can reach ticket buyers, and it reaches them silently.
- **Where:** [FACTS.md](../FACTS.md) row 15 and history rows 9 to 13, [entities/room-4.md](../entities/room-4.md), [entities/workshops-area.md](../entities/workshops-area.md), [summaries/C03-house-rules.md](../summaries/C03-house-rules.md)
- **Evidence:**
  - "Maximum tickets equals room capacity plus 20 percent" (C03, organiser note, 2026-09-13).
  - Capacities changed on 2026-09-19 (C02): Room 4 from 20 to 25, cafeteria from 120 to 96, Rooms 1 to 3 upward.
- **Why it matters:** The rule is a formula on a value that moved after the rule was published. Every event page built before 2026-09-19 carries a cap computed from the old capacity. Room 4 sessions are now under-sold against the room, the cafeteria is over-sold against it, and the cafeteria case means more tickets than seats.
- **Suggested resolution:** No wiki value is wrong, so nothing in FACTS.md changes. Outside the wiki: list the event pages created before 2026-09-19, recompute the cap from rows 9 to 14, and correct the cafeteria pages first, since only those oversell.
- **Decision by:** House organisers (owner of row 15).

### 3. Facts without an owner: rows 8 to 14

- **Severity:** Medium. FACTS.md rule 2 requires an owner on every row, and without one finding 1 cannot be decided.
- **Where:** [FACTS.md](../FACTS.md) rows 8, 9, 10, 11, 12, 13, 14
- **Evidence:** C02 names its author as "Read from the planning backoffice", a system, not a person or a role. No source in this wiki names who decides a seat count or the rooftop window.
- **Why it matters:** An owner is the tie-breaker when sources disagree. Seven of twenty rows currently have no tie-breaker, including the one contested row.
- **Suggested resolution:** Name the role that owns room capacity, most likely a venue or operations role among the organisers, and write it into rows 9 to 14. Assign row 8 to whoever owns the rooftop relationship. This is an assignment by the maintainers, not a value taken from a source.
- **Decision by:** House organisers.

### 4. Gap: the number of API credit redemptions is not stated

- **Severity:** Medium. A workshop host who promises credits cannot tell how many are covered.
- **Where:** [FACTS.md](../FACTS.md) row 20, [summaries/C03-house-rules.md](../summaries/C03-house-rules.md)
- **Evidence:** "The link accepts a fixed number of redemptions. One redemption per person" (C03, 2026-09-13). The number itself does not appear in any source.
- **Why it matters:** The rule says a wrong account ID cannot be fixed afterwards, so a participant who misses the cap has no second attempt.
- **Suggested resolution:** Ask the organisers for the number and ingest the answer as a new source. Do not estimate it from room capacity.
- **Decision by:** House organisers.
