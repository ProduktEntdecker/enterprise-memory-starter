1 · The map problem

Not a memory problem.
A map problem.

Context is finite

Every token spends attention.

Loading everything is not an option.

So give the agent a map

Know where to look.

Then load only what the question needs.

Source: Anthropic, Effective context engineering for AI agents (2025). Own observation: the map framing.3 / 19

2 · RAG, the good part

What RAG does well

Large corpora

Scales far past what fits in any context window.

Unknown questions

Retrieves at question time, including the long tail.

Fresh documents

Add a file to the index. No retraining.

Sources: Anthropic, Contextual Retrieval (2024); Lewis et al., RAG, NeurIPS 2020; Sarthi et al., RAPTOR (2024).4 / 19

2 · RAG, the good part

Summaries on top of retrieval help

RAPTOR builds its tree with embeddings and clustering, then retrieves across summary levels.

+20%

absolute accuracy on QuALITY with GPT-4, over the previous best result

Evidence that summaries on top of retrieval help. Not evidence that hierarchy beats vector search.

5 · When to use which

Compile what matters. Retrieve the rest.

Root mapalways loaded
LLM wikicurated, recurring, canonical
RAG over raw sourceslarge, unforeseen, fresh
↑Promote recurring answers into the wiki
↓Fall back to retrieval when no page exists

Under about 200K tokens? Load it all. No retrieval needed.
